# 確定申告支援ツール(kakuteishinnkoku)

日本の個人向け確定申告を支援するセルフホスト型Webアプリ。
暗号資産・株式等投資の損益計算と、マネーフォワード MEからのデータ取り込みに対応する。

このリポジトリは「ルーティンごとにブラッシュアップする」開発方針で育てている。
1回のセッションで全部を作り切るのではなく、都度機能を積み増していく。
現在の到達点と次にやるべきことは、このREADME末尾の「ロードマップ」を参照。

## 技術スタック

- Next.js 16 (App Router, Server Actions) + TypeScript
- Tailwind CSS v4
- Prisma 6 + SQLite(ローカルファイルDB。個人利用前提でクラウドDBは使わない)
- decimal.js(金額計算を浮動小数点誤差なく行うため、円建て金額は全てDecimalで扱う)
- Vitest(計算ロジックのユニットテスト)

## 機能(現時点)

### 0. 前年繰越残高(期首残高) — `src/lib/openingBalance.ts`

複数年にまたがって暗号資産・株式等を保有している場合、総平均法・移動平均法の
計算にはその年の期首時点の保有数量と取得価額合計が必要になる。`/import`
ページの「期首残高(前年からの繰越)」セクションから、銘柄ごとに期首残高を
手入力できるほか、「前年の期末残高から自動で繰り越す」ボタンで前年分の
計算結果(期末残高)をそのまま当年の期首残高として一括登録できる
(既に登録済みの銘柄は上書きしない)。NISA口座分は課税口座と別ロットとして
別途登録する。

### 1. 暗号資産(仮想通貨)の損益計算 — `src/lib/crypto/`

国税庁の「暗号資産に関する税務上の取扱いについて(FAQ)」に基づき雑所得を計算する。
購入・売却・暗号資産同士の交換(TRADE_IN/TRADE_OUT)・マイニング等の受取
(INCOME)・暗号資産建て手数料(FEE)に対応。

暗号資産取引所(bitFlyer・Coincheck・GMOコイン等)の「取引履歴」CSVも
`src/lib/crypto/exchangeCsv.ts` から取り込める。よく使われる列見出しは
エイリアスで自動判定しつつ、一致しないCSVは `/import` 画面でヘッダー名を
ユーザー自身が指定する汎用マッピング方式でも取り込める。これにより、未検証の
取引所固有フォーマットを誤って解釈するリスクを避けながら、仕様変更や表記ゆれの
あるCSVにも対応する。現状は円建ての現物売買(買い/売り)のみに対応しており、
暗号資産同士の交換やマイニング等の受取はCSVからは取り込めない(手入力で対応する)。

評価方法は**総平均法**(届出が無い場合の法定算出方法。その年の期首残高と
年間取得分を合算した加重平均単価を、その年の全ての譲渡に適用する)と
**移動平均法**(税務署への届出により選択可能。取得の都度平均単価を更新し、
譲渡時点の平均単価を取得費とする)のいずれかを、課税年度ごとにダッシュボードから
選択できる(`TaxYear.cryptoCostMethod`)。移動平均法を選ぶ場合は各取引の取引日時
(tradedAt)が計算に必須になる。

暗号資産取引所(bitFlyer・Coincheck・GMOコイン等)の「取引履歴」CSVも
`src/lib/crypto/exchangeCsv.ts` から取り込める。取引所ごとに専用パーサーを
用意するのではなく、日時・銘柄ペア・売買種別・数量・単価(または合計金額)・
手数料という共通項目に対して、よく使われる列見出し表記をエイリアスとして
幅広く登録する汎用パーサーとして実装している。現状は円建ての現物売買
(買い/売り)のみに対応しており、暗号資産同士の交換やマイニング等の受取は
CSVからは取り込めない(手入力で対応する)。

### 2. 株式・投資信託等の譲渡損益計算 — `src/lib/investment/`

所得税法施行令118条に基づく「総平均法に準ずる方法」(実務上の移動平均法)で
取得費を計算し、譲渡所得(申告分離課税)を算出する。NISA口座は課税口座と
別ロットとして扱い、非課税の参考値として分離表示する。配当等は損益計算とは
別に集計する。

### 3. マネーフォワード ME 連携 — `src/lib/moneyforward/`

マネーフォワード MEの「家計簿」CSVエクスポートを取り込める。ヘッダー名で
カラムを特定するため列順の変更に強く、1行の解析に失敗しても
(不正な日付・金額など)その行だけスキップして処理を継続する。

### 4. 暗号資産取引所CSVの取り込み — `src/lib/crypto/exchangeCsv.ts`
bitFlyer(現物取引履歴CSV)・Coincheck(業界標準フォーマットCSV)・GMOコイン
(取引履歴CSV)・bitbank(約定履歴CSV)のエクスポートファイルを取り込める。
いずれも現物取引の行のみが対象で、信用・証拠金取引やレバレッジ取引の行は
自動では取り込まずスキップする(建玉の決済損益で課税所得が決まるため、
本ツールの現物取引モデルにはそのまま当てはめられない)。各取引所のCSV仕様は
非公式(取引所側の仕様変更で崩れる可能性がある)なため、マネーフォワードの
パーサーと同様「解釈できない行はスキップして処理を継続し、件数を報告する」
方針を取る。特に入出金(送付・受取)・証拠金取引・税務上の性質が一意に
決まらない明細(増加/減少の一方のみの行など)は誤って課税イベントとして
取り込むより安全側に倒してスキップし、必要であれば手動登録を促す。
取り込んだ内容は必ず `/import` の一覧で確認すること。また、列見出しが
プリセットと一致しないCSVや未検証の取引所CSVは、`/import` 画面で
日付/銘柄/売買種別/数量/単価/手数料の列名を指定する**汎用マッピング方式**
でも取り込める。

bitbankの「約定履歴」CSVも同様に取り込める。「現物/信用」列が"現物"の行のみを
対象にし、信用取引の行は対象外としてスキップする。

### 5. 前年繰越残高(期首残高)の管理 — `src/lib/openingBalance.ts`

暗号資産・株式等とも、複数年にまたがって保有している場合の期首残高を
`/import` 画面から登録できる。銘柄ごとに手入力するほか、「{前年}年分の
期末残高から繰り越す」ボタンで前年分の取引から期末残高を自動計算し、
当年分の期首残高として一括登録できる(既存の登録は上書きされない)。
株式等はNISA口座・課税口座を別ロットとして繰り越す。

### 6. 配当所得の課税方式シミュレーション — `src/lib/investment/dividendTaxSimulation.ts`

上場株式等の配当所得について、総合課税・申告分離課税・申告不要のどの方式を
選ぶと税負担が最も軽くなるかを試算する(ダッシュボードの「配当所得の課税方式を
シミュレーションする」から利用)。配当以外の課税所得金額や、損益通算できる
上場株式等の譲渡損失額を入力すると、方式ごとの国税・住民税の試算額と、
配当控除額・損益通算に使った損失額を比較表示する。所得税は速算表による
超過累進税率、住民税は10%固定(均等割は含まない)で計算する概算値であり、
配当控除率は上場株式(普通配当)を前提とする(投資信託等の分配金は控除率が
異なるため、複数銘柄が混在する場合は概算として扱うこと)。
### 7. 上場株式等の譲渡損失の繰越控除(3年間) — `src/lib/investment/lossCarryforward.ts`

確定申告により繰越控除の適用を受けた上場株式等の譲渡損失は、発生した年の
翌年以後3年間、上場株式等の譲渡所得等の金額から控除できる(暗号資産の損失は
雑所得のため損益通算・繰越の対象外)。`/import`ページの「上場株式等の譲渡損失の
繰越控除(3年間)」セクションから、発生年ごとに年初時点で残っている繰越損失残高を
手入力できるほか、「前年分の計算結果から自動で繰り越す」ボタンで前年分の
繰越控除計算結果(未使用の繰越残高)をそのまま当年分に一括登録できる
(既に登録済みの発生年は上書きしない)。控除は発生年の古いものから優先して
適用し、発生年から3年を超えた残高は自動的に控除対象から除外(期限切れとして
表示)する。ダッシュボードの「譲渡所得(株式等)」は繰越控除適用後の課税対象額を
表示し、下書きCSV(`src/lib/etax/csvExport.ts`)にも繰越控除の使用額・翌年繰越額・
期限切れ額を出力する。

### 8. 暗号資産の証拠金(レバレッジ)取引の決済損益 — `src/lib/crypto/marginCalculator.ts` / `src/lib/crypto/marginCsv.ts`

DMM Bitcoin・SBI VCトレード等の証拠金(レバレッジ)取引は、現物取引のように
数量×単価で取得費を積み上げる総平均法/移動平均法の計算モデルにはあてはまらず、
決済(反対売買)のたびに確定する**建玉損益**がそのまま雑所得の収入・損失になる。
そのため`CryptoTrade`(現物)とは別に`CryptoMarginTrade`テーブルを設け、決済ごとの
損益(手数料控除・スワップポイント加算後)を単純に合算するだけのシンプルな
計算エンジンとした(期首残高・取得原価の概念を持たない)。`/import`ページの
「暗号資産の証拠金(レバレッジ)取引の決済損益」セクションから手入力できるほか、
取引所ごとのCSV仕様の差異が大きく未検証のため専用プリセットは用意せず、
決済日時・銘柄・決済損益・手数料・スワップの列名を指定する汎用マッピング方式で
CSV取り込みにも対応する。ダッシュボードの「雑所得(暗号資産)」・下書きCSVの
出力額は、現物取引分と証拠金取引分の合計値を表示する。

### 9. 証券会社の特定口座年間取引報告書との突合 — `src/lib/investment/annualReportReconciliation.ts`

証券会社が発行する「特定口座年間取引報告書」の「譲渡の対価の額(収入金額)」
「配当等の額」を、証券会社・口座区分ごとに`/import`画面から入力すると、
アプリに登録済みの同じ証券会社・口座区分の売却・配当の取引明細から計算した
金額と自動で突き合わせ、差額があれば「不一致」として一覧に表示する
(1円未満の端数差は許容する)。収入金額・配当等の額はその年の実績値の
単純合計として計算できるため、前年繰越や取得費の平均単価計算に依存せずに
検証でき、証券会社の記録と照合することで取引の入力漏れ・入力ミスを検知
できる。「取得費及び譲渡に要した費用の額等」は証券会社が口座ごとに個別
管理する取得原価であり、本ツールの譲渡所得計算(`src/lib/investment/calculator.ts`)
は銘柄単位・全口座合算で平均単価を計算するため前提が異なる(同一銘柄を
複数の証券会社・口座で保有している場合、口座ごとの取得費は一致しない)。
そのため取得費・差引金額は自動突合の対象にはせず、参考表示のみ行う。

### 10. 確定申告書作成コーナー向け下書きCSV出力 — `src/lib/etax/`

暗号資産・投資の年間集計を、申告書の該当欄と対応付けたCSVとして
ダウンロードできる(ダッシュボードの「下書きCSVをダウンロード」ボタン)。

**重要な制約:** 個人が保有するマイナンバーカードでe-Taxへ電子署名・送信する
処理は、国税庁の「確定申告書等作成コーナー」または「e-Taxソフト」経由でしか
行えない。第三者ツールが認証情報を代行してe-Taxへ直接送信する公式なAPIは
存在しないため、本ツールはe-Taxへの自動送信は行わない。出力されるCSVは
あくまで「確定申告書等作成コーナー」に転記する際の下書き・集計資料であり、
国税庁公式のインポート形式ではない。

### 11. マネーフォワード資産残高との突合(取引漏れ検出) — `src/lib/moneyforward/`

マネーフォワード ME の「資産の内訳」画面からダウンロードしたCSV(資産残高
スナップショット)を取り込み、残高がある金融機関(取引所・証券会社)の
うち、アプリに同じ名前の暗号資産・投資取引明細が1件も登録されていない
ものを「計上漏れの疑い」として`/import`画面に一覧表示する。逆に、アプリ
には取引明細があるのにマネーフォワード側の資産残高に見当たらない金融機関も
参考情報として表示する(資産の移管やマネーフォワード未連携の口座でも
起こりうるため、こちらは計上漏れとは限らない)。

証券会社の年間取引報告書との突合(機能9)と同様、この突合は自動判定できる
範囲(ここでは金融機関名の一致)に限定している。マネーフォワード側の
資産名の表記(例:「ビットコイン」)とアプリ側の銘柄シンボル(例:「BTC」)
の対応は自動判定できないこと、評価額は時価に左右され取得原価ベースの
保有数量と単純比較できないことから、銘柄単位での数量・評価額の自動比較は
行わない。金融機関名はアプリ側の取引所名・証券会社名の入力と完全一致
(前後の空白のみ正規化)で突き合わせるため、表記を揃えて登録する必要がある。
CSVの列見出しは公開情報から確認できておらず未検証のため、専用プリセットは
用意せず、暗号資産取引所CSVの手動マッピング方式と同様に列名を指定する
汎用マッピングのみで取り込む。

## データモデル

`prisma/schema.prisma` を参照。主なテーブル:

- `TaxYear` — 課税年度(暦年)単位でデータを区切る
- `CryptoTrade` — 暗号資産(現物)の取引明細
- `CryptoMarginTrade` — 暗号資産の証拠金(レバレッジ)取引の決済損益明細
- `InvestmentTrade` — 株式・投資信託等の取引明細(口座区分・NISA区分を保持)
- `OpeningBalance` — 各課税年度の期首残高(前年繰越分の保有数量・取得価額)
- `InvestmentLossCarryforward` — 上場株式等の譲渡損失の繰越控除残高
  (発生年ごとの、各課税年度初時点での未使用残高)
- `BrokerAnnualReport` — 証券会社の特定口座年間取引報告書との突合用の
  年間サマリー数値(証券会社・口座区分ごとの収入金額・取得費・配当等の額)
- `AssetBalanceSnapshot` — マネーフォワードの資産残高突合用の、金融機関・
  資産別の残高スナップショット
- `ImportBatch` / `CashflowEntry` — マネーフォワード等からの取り込みバッチと明細

## ロードマップ(次回以降のブラッシュアップ候補)

優先度が高いと思われる順:

1. **暗号資産取引所CSVの実データ検証・対応拡大** — bitFlyer・Coincheck・
   GMOコイン・bitbankの実エクスポートCSVで列見出し・値の揺れを検証し、
   一致しないものは`src/lib/crypto/exchangeCsv.ts`のプリセットやエイリアスに
   反映する(特にbitbankは公開情報から推定した仕様のため実データでの検証が
   未了)。手動マッピング欄に対しては、よく使われる列名の組み合わせを補完する
   プリセット等の入力補助も検討する。証拠金取引の決済損益CSV
   (`src/lib/crypto/marginCsv.ts`)も同様に、DMM Bitcoin/SBI VCトレード等の
   実データに基づくプリセット化は今後の課題。
2. **証券会社の特定口座年間取引報告書のCSV/PDF自動取り込み** — 現状は
   `/import`画面から報告書の金額(収入金額・取得費・配当等の額)を手入力する
   方式(`src/lib/investment/annualReportReconciliation.ts`)のみ対応している。
   証券会社ごとに様式が異なるCSV/PDFを解析して自動入力できるようにすれば、
   転記の手間と入力ミスをさらに減らせる。
3. **マネーフォワード資産残高突合の精度向上** — 現状は金融機関名の一致のみで
   突合している(機能11参照)。マネーフォワードの資産名と銘柄シンボルの
   対応表(例:「ビットコイン」→BTC)をユーザーが登録できるようにすれば、
   銘柄単位での保有数量の突合まで踏み込める可能性がある。
4. **認証・マルチユーザー対応** — 現状は単一ユーザーのローカル利用を想定。
   将来的にホスティングする場合はログイン機能が必要。

  `src/lib/moneyforward/assetBalanceReconciliation.ts`・`/import`の専用

- **証券会社の特定口座年間取引報告書との突合(手入力)**

  入力すると、アプリ内の取引明細から計算した同条件の合計値と自動で突き合わせ、
  差額があれば一覧に表示する。取得費は口座ごとの管理と本ツールの計算前提が
  異なるため自動突合の対象外とし、参考表示に留めた。CSV/PDFからの自動取り込み
  は未対応(今後の課題、ロードマップ参照)。
- **暗号資産の証拠金(レバレッジ)取引の決済損益への対応**
  (`CryptoMarginTrade`テーブル・`src/lib/crypto/marginCalculator.ts`・
  `src/lib/crypto/marginCsv.ts`・`/import`の専用セクション)。DMM Bitcoin/SBI

  現物取引とは別のシンプルな合算モデルとして実装し、ダッシュボード・下書き
  CSVでは現物取引分と合算した雑所得(暗号資産)を表示する。
- **bitbankの約定履歴CSV取り込み**(`src/lib/crypto/exchangeCsv.ts`)。

## 免責事項

本ツールは税額計算を補助するための個人開発ツールであり、税務署・国税庁の
公式ツールではない。計算結果の正確性を保証するものではなく、実際の申告内容は
必ず国税庁「確定申告書等作成コーナー」の計算結果や、税理士等の専門家の確認を
受けること。
